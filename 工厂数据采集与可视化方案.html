01 / SCOPE

先划清边界，再谈炫技

纯前端不是「只画图的看板皮肤」，它要把采集编排、数据归一、渲染和交互一起扛下来。同时它有一条硬边界：浏览器读不到 PLC 的原始协议。

定位：车间里的一块「活」数据墙

车间大屏、班组电脑、值班手机各看各的版本，这件事本身就消耗信任。方案把三维布置图、设备状态、产量与 OEE 收进一个页面，同一套状态色、同一个时间基准，谁看都是同一张图。

所有数据走一条只读通道进浏览器，页面只负责"呈现 + 交互"，不做任何写操作。这既符合产线安全要求，也让整个系统可以退化成一份静态资源：两个库落到本地后，断网也能打开。

只读接入 单文件交付 无后端 状态同源
事项归属
协议接入边缘网关（OPC UA / Modbus → HTTP、WebSocket）
数据采集编排本方案：订阅 + 轮询 + 本地发生器三路合流
历史归档不做。前端只保留滑动窗口与当班汇总
账号与权限不做。大屏按物理位置隔离，不做登录态
告警处置只展示与定位，不承接派单流程
三维场景本方案：等轴测布置图 + 状态映射

明确不做的事，比能做的事更能定住方案。

02 / DATA PATH

数据从设备走到像素

五个环节，每一环只做一件事。前端从第 3 环节开始接手，这也是纯前端方案唯一真正被卡住的地方。

01 / FIELD

现场设备

加工中心、装配工位、AGV、电表与温湿度传感器。原始数据只有点位与时间戳，没有语义。

边缘网关

浏览器不可直达

采集层（前端）

统一时间戳、单位与状态枚举，落进环形缓冲；OEE、节拍、达成率等派生指标在这里算。

05 / RENDER

渲染与交互

统计图表交给 ECharts，车间空间关系交给 Three.js，状态文字与操作交给 DOM。

2D + 3D 同源

三条可行通道，按现场条件选

通道适用代价
WebSocket秒级刷新、状态变化频繁需网关长连接与心跳
SSE只需服务端推送、实现最轻单向，不能回传
轮询5 分钟以上汇总、跨网段最稳延迟高，请求次数多

浏览器的真实限制

页面不能直连 Modbus / OPC UA，也不能在无人授权时反复重连。方案里用三条约定兜住：

  • 网关必须暴露只读端点，页面不携带任何写指令
  • 断流时保留最后有效值并标记「数据陈旧」，不显示成 0
  • 虚拟发生器与真实数据同结构，切换时只换数据源不换渲染
03 / MODEL

一张设备快照撑起整页

所有图、所有状态色、三维里每一台机器的颜色，都从同一条快照读出来。模型错了，后面全是补丁。

四张核心表

表主键关键字段
devicesdevice_idline、type、state、x/z 坐标、朝向
pointspoint_idunit、采样周期、上下限、所属设备

三维坐标写进 devices 表，是这套方案跟普通看板最大的不同：空间位置也是数据。

归一三原则

  • 时间是唯一基准：所有点带同一时间戳，渲染层不再自己取 now()
  • 状态收敛为 RUN / IDLE / WARN / DOWN 四态，未知一律 DOWN 灰显
  • 单位在入口换完：℃、mm/s、kWh、件/小时，页面里不再做换算

虚拟发生器的三层结构

随机的钱最不值钱。发生器按能解释的规律造数，所以图上的波动都读得出来原因：

层规则
基线白班系数 1.0、夜班 0.82，按班次正弦过渡
噪声±6% 随机游走，按设备型号给不同方差
事件手动「注入故障」→ DOWN 12 秒 → WARN → RUN

三条挂在页面上的操作

样机要能证明"数据真的在动"，而不只是一张图。

  • 暂停采集：冻结发生器，图与三维同时停在当前帧
  • 注入故障：随机一台设备转故障，三维灯带变红、统计图同步变化
  • 点选设备：三维里点哪台，右侧读数就换成哪台
05 / 3D SCENE

第三个维度用来交代位置与尺度

车间不是一排表格：设备的远近、产线的朝向、AGV 走的通道，本身就是信息。所以这里用等轴测而不是透视，像一张可旋转的布置图。

状态色怎么落到模型上

运行RUN
机身灯带常亮，节拍灯随加工闪一次
待机IDLE
灯带压暗到 30%，不抢注意力
预警WARN
灯带慢速呼吸，1.2 秒一个循环
故障DOWN
灯带高亮 + 地面落一块红色光斑

动效只在预警与故障上使用——静止的车间不该有东西在动。

三条硬约束

  • 视角限位：方位角 ±30°、俯角 22°–55°，任何角度都是成立的构图
  • 点选即读数：射线拾取到设备后，HUD 换成该台设备的快照
  • 有明暗层次：主光定形体、补光读暗部、环境反射把金属从黑底里剥出来

性能与降级

预算项上限 / 做法
三角面< 8 万，重复设备用实例化
draw call约 150，上限 200；同类材质合并
像素比≤ 2，移动端降到 1.5
离屏标签页不可见即停渲染循环

字体分工

Barlow Semi Condensed 承担标题与英文标签，窄体带工程味。

JetBrains Mono 只给数字、编号、图纸参数——等宽让读数对齐。

中文正文走系统字（思源 / 苹方 / 雅黑），不额外拉中文网页字。

层级与栅格

12 列栅格，8px 基距，所有间距落在 4 的倍数上。

正文 14px / 行高 1.75；说明 11.5px；数字读数 13px 等宽。窄屏正文不低于 14px。

用色纪律

青色覆盖面积控制在视口 5% 以内，只出现在实时状态、焦点与结论数字。

琥珀与砖红不参与装饰，只表示等级。图表系列色全部从青—灰区间派生，不用默认色轮。

07 / BUILD & ROLLOUT

怎么把它做出来、怎么验收

演示用单文件；真正上产线时按模块拆开，但数据契约与渲染层保持同一套。

工程结构

factory-visual/ ├─ 工厂数据采集与可视化方案.html ← 单文件交付 ├─ src/ 拆开开发时的源码（可选） │ ├─ ingest/ ws.js · poll.js · mock.js │ ├─ store/ normalize.js · ring.js │ └─ render/ charts.js · scene.js · hud.js └─ assets/ 设备标识 · 字体子集

单文件版本把 ingest / store / render 三段代码放在同一个 <script> 里，按注释分段；拆开时只搬函数，不改数据契约。

四周落地节奏

P0 · 第1周
接口契约

定快照字段、单位、状态枚举，先出静态假页。

P1 · 第2–3周
采集与图表

三路数据源合流、环形缓冲、三张统计图跑通。

P2 · 第4–5周
三维场景

布置图建模、状态映射、点选读数、性能档位。

P3 · 第6周
联调与上墙

接真网关、大屏实测、断流与降级演练。

交付前必须成立的事

  • 断流时界面显示「数据陈旧」而不是 0 值
  • 三维里每台设备的颜色与列表状态完全一致
  • 无 WebGL 的机器上仍能看到布置图与全部读数
  • 大屏 1920 与笔记本 1366 下不出现横向滚动
  • 手机端图表宽度占满视口，文字不小于 14px
  • 连续运行 8 小时内存无持续增长（缓冲有上限）
